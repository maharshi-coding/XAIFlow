# Demonstration

1. Start the services and create a project. Upload `data/demo_churn.csv` and select `churn`. Inspect preview, missing counts, column types and class distribution. The 320-row data is synthetic and generated by `scripts/generate_demo.py` with seed 42.
2. Open Pipelines. Build `Dataset → Impute → Encode → Scale → Split → Logistic Regression → Evaluation → LIME → Register → Deploy`. Select the uploaded dataset, use median imputation, one-hot encoding, standard scaling and a stratified 25% holdout.
3. Save and validate. Run it. Watch node status and logs; open its experiment to inspect metrics, the confusion matrix and local feature contributions.
4. Create the random forest flow ending in SHAP and Register. Execute with 60 trees/max depth 8. Change it to 100 trees and run again. Select both experiments to compare parameters, metrics, elapsed time, artifacts and explanation availability. Older snapshots remain intact.
5. Create the PyTorch flow ending in LIME and Register. Use hidden dimensions `[24,12]`, 30 epochs and seed 42. Inspect loss history, metrics and local explanations. Model bundles and explicit weights are persisted.
6. Open Models and inspect version/lineage. Deploy a version if it was not deployed by the pipeline. In Deployments, send a raw-feature sample with `explain: "lime"` or `"shap"`. Inspect prediction, probabilities, method and model metadata. Send an invalid schema to observe a structured error.
7. Open Monitoring for the deployment. Submit a controlled numeric shift of 4 standard deviations. Inspect actual request count, PSI, distribution changes and the persistent drift alert. Acknowledge the alert in Alerts. Optional ground-truth `labels` enable accuracy/degradation checks.
8. Create and download a backup. Restore it through Backups. Select the restored project and verify its datasets, saved pipelines, experiment metrics, registry versions, deployment and inference. The source and unrelated projects keep their own identities.

For repeatable preparation, `python3 scripts/demo.py --run` performs the three training flows and two forest experiments via the same HTTP APIs used by the UI. This creates a new demo project each time; it never replaces prior experiments.
